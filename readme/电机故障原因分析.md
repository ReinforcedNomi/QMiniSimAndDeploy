# 电机故障原因分析

## 概述

本文档分析代码中可能导致电机报故障状态、导致无法控制的各个部分。

---

## 一、电机故障检测

从代码中可以看到，电机状态包含 `merror` 字段（电机错误状态）：

```cpp
// example_goM8010_6_motor.cpp
std::cout << "motor.merror: " << data.merror << std::endl;
```

`merror` 通常包含电机内部检测到的故障信息。

## 二、可能导致电机故障的原因

### 2.1 位置超出限位（位置保护）

**位置**：`rl_controller.cpp` 多处位置限位检查

**代码位置**：
```cpp
// 第153行：RL控制模式
joint_act = joint_act.cwiseMax(act_pos_low).cwiseMin(act_pos_high);

// 第476行：站立控制模式
joint_act = joint_act.cwiseMax(act_pos_low).cwiseMin(act_pos_high);

// 第495行：正弦测试模式
joint_act = joint_act.cwiseMax(act_pos_low).cwiseMin(act_pos_high);

// 第543行：模拟步态模式
joint_act = joint_act.cwiseMax(act_pos_low).cwiseMin(act_pos_high);
```

**问题**：
- 虽然代码中进行了限位检查，但如果电机实际位置超出硬件限位，电机可能会报故障
- `act_pos_low` 和 `act_pos_high` 配置错误可能导致软件限位和硬件限位不匹配
- 如果目标位置在限位边界附近，由于控制误差，实际位置可能超出硬件限位

**当前限位配置**（config.yaml）：
```yaml
act_pos_low: [ -0.3, -0.6, -2.1, -0.7, -2.5, -0.5, -0.2, 0, -2.1, -0.3 ]
act_pos_high: [ 0.5, 0.0, 0., 0.0, 0.1, 0.1, 0.5, 2.1, 0.6, 2.5 ]
```

**风险点**：
- 关节7的下限为0，如果初始位置在负值，可能导致问题
- 关节2的上限为0，限制较严格
- 关节3的上限为0，限制较严格

---

### 2.2 速度过大（速度保护）

**位置**：`rl_controller.cpp` 的 `smooth_joint_action()` 函数

**代码位置**：
```cpp
// 第437-444行：速度限制
for (int i = 0; i < NUM_JOINTS; ++i) {
    float vel_magnitude = std::abs(desired_vel[i]);
    if (vel_magnitude > max_vel) {
        desired_vel[i] = desired_vel[i] / vel_magnitude * max_vel;
    }
}
```

**问题**：
- **RL控制模式**（`joint_increment_control`）没有速度限制！
  ```cpp
  // 第152行：直接积分，没有速度检查
  joint_act.segment(0, NUM_ACTUAT_JOINTS) += 
      increment.segment(NUM_LEGS, NUM_ACTUAT_JOINTS) * _rl_time_step;
  ```
  如果 `increment` 很大或 `_rl_time_step` 不准确，可能导致速度过大

- **动作增量范围**（config.yaml）：
  ```yaml
  act_inc_high: [ 3.5, 15. ]  # 相位频率增量上限3.5，关节位置增量上限15 rad/s
  act_inc_low: [ 0.5, -15. ]  # 关节位置增量下限-15 rad/s
  ```
  如果模型输出接近±15 rad/s，实际速度可能过大

- **控制周期不准确**：如果 `_rl_time_step` 实际值大于设定值（0.01s），会导致速度被放大

**风险点**：
- RL模式中，如果ONNX模型输出接近±1（映射到±15 rad/s），且控制周期波动，可能导致瞬时速度过大
- 没有对 `joint_vel`（实际关节速度）进行检查和限制

---

### 2.3 堵转保护（位置误差过大）

**位置**：`rl_controller.cpp` 的 `smooth_joint_action()` 函数

**代码位置**：
```cpp
// 第407-413行：堵转保护检查
// 避免因为惯性导致无法及时到达目标位置而触发堵转保护
float max_error = current_error.cwiseAbs().maxCoeff();
if (max_error > 0.5f) {
    // 如果位置误差超过0.5弧度，进一步降低速度
    max_vel = max_vel * 0.7f;  // 降低30%的速度
}
```

**问题**：
- **只在stand模式有效**，RL模式没有类似保护
- 如果目标位置和实际位置差距持续超过阈值，电机可能认为堵转
- 位置误差阈值（0.5弧度）可能不够，某些关节可能需要更小的阈值

**风险点**：
- RL模式下，如果模型输出导致目标位置突然变化，而实际位置跟不上，可能触发堵转
- 初始化时，如果 `init_joint_act` 和实际位置差距很大，可能导致堵转

---

### 2.4 加速度过大（加速度保护）

**代码中缺少加速度限制！**

**问题**：
- 代码中没有对关节加速度进行限制
- 如果目标位置变化过快，会导致加速度过大
- 特别是RL模式下，模型输出可能突然变化

**风险点**：
- 平滑关节动作时，如果 `max_vel` 设置过大，启动瞬间加速度可能很大
- RL模式下，动作增量直接积分，没有加速度限制

---

### 2.5 力矩过大（力矩/电流保护）

**代码位置**：
```cpp
// 第302行：前馈力矩始终为0
motor_command_tmp.tau_ff[i] = 0.;
```

**问题**：
- 虽然前馈力矩为0，但如果kp/kd设置过大，位置误差或速度误差大时，PD控制产生的力矩可能很大
- **刚度系数**（config.yaml）：
  ```yaml
  kp: [ 1, 0.5, 1.5, 1, 1, 1, 0.5, 1.5, 1, 1 ]
  ```
  如果位置误差较大，力矩 = kp × 位置误差，可能超过电机最大力矩

**风险点**：
- 如果位置误差持续较大（例如0.5弧度），kp=1.5的关节产生的力矩 = 0.75 N·m，可能较大
- 速度误差大时，kd产生的阻尼力矩也可能较大

### 2.6 控制命令异常

**位置**：`rl_controller.cpp` 的 `set_rl_joint_act2dds_motor_command()` 函数

**代码位置**：
```cpp
// 第289行：直接使用joint_act作为目标位置
motor_command_tmp.q_target[i] = joint_act[jointIndex2Sim[i]];
```

**问题**：
- 如果 `joint_act` 包含 NaN 或 Inf，会导致电机命令异常
- 如果 `joint_act` 没有被正确初始化或更新，可能发送错误命令

**风险点**：
- ONNX模型输出异常（虽然被裁剪到[-1,1]）
- 观测向量包含异常值（虽然被裁剪到[-3,3]）
- 计算过程中出现数值溢出

---

### 2.7 通信异常

**位置**：DDS通信和串口通信

**问题**：
- DDS通信延迟或丢包，导致控制命令不及时
- 串口通信故障（Motor_thread.hpp中的串口通信）
- 传感器数据异常，导致观测向量错误，进而导致控制命令错误

**风险点**：
- 如果传感器数据长时间不更新，`joint_pos` 和 `joint_vel` 可能过时
- 如果控制命令发送失败，电机可能保持上次命令，导致位置偏差累积

---

### 2.8 初始化问题

**位置**：`rl_controller.cpp` 的 `init()` 和 `reset()` 函数

**代码位置**：
```cpp
// 第77行：初始关节动作设为参考位置
joint_act = _ref_joint_act;

// 第104行：reset时，如果不在test模式
joint_act = joint_pos;  // 使用当前实际位置
init_joint_act = joint_pos;
```

**问题**：
- 如果初始位置和 `_ref_joint_act` 差距很大，可能导致瞬间大动作
- 如果 `joint_pos` 读取错误（例如传感器故障），初始化位置可能错误

**风险点**：
- 机器人启动时，如果关节不在零位，切换到stand模式可能导致大动作
- reset时，如果实际位置读取错误，可能导致后续控制错误

## 三、当前代码的保护措施

### 3.1 已有的保护

1. **位置限位**：多处使用 `cwiseMax/cwiseMin` 限制位置
2. **速度限制**：stand模式中有速度限制（max_vel = 0.1-0.18 rad/s）
3. **堵转保护**：stand模式中有位置误差检查（>0.5弧度时降低速度）
4. **观测值裁剪**：观测向量裁剪到[-3, 3]
5. **动作输出裁剪**：ONNX输出裁剪到[-1, 1]

### 3.2 缺失的保护

1. **RL模式速度限制**：RL模式下没有速度检查
2. **加速度限制**：完全没有加速度限制
3. **位置误差持续监控**：没有持续监控位置误差是否过大
4. **电机状态检查**：代码中没有检查 `merror`（电机错误状态）
5. **数值异常检查**：没有检查 NaN/Inf

void RLController::joint_increment_control(Matrix<float, Dynamic, 1> increment) {
    pm_f = increment.segment(0, NUM_LEGS);
    compute_pm_phase(pm_f);
    
    // 添加速度限制
    Vec10<float> desired_vel = increment.segment(NUM_LEGS, NUM_ACTUAT_JOINTS);
    float max_vel = 3.0f;  // 最大速度限制（rad/s），可配置
    
    for (int i = 0; i < NUM_ACTUAT_JOINTS; ++i) {
        if (std::abs(desired_vel[i]) > max_vel) {
            desired_vel[i] = std::copysign(max_vel, desired_vel[i]);
        }
    }

}

## 五、故障排查步骤

如果电机报故障，按以下步骤排查：

1. **检查位置是否超出限位**
   - 查看 `joint_pos` 是否在 `act_pos_low` 和 `act_pos_high` 范围内
   - 检查是否有关节接近或超出硬件限位

2. **检查速度是否过大**
   - 查看 `joint_vel` 的值
   - 检查是否有关节速度超过合理范围（例如>5 rad/s）

3. **检查位置误差**
   - 计算 `joint_act - joint_pos`，查看是否过大（>0.5弧度）
   - 检查误差是否持续存在

4. **检查控制命令**
   - 查看 `joint_act` 是否包含异常值（NaN/Inf）
   - 检查 `kp` 和 `kd` 是否设置合理

5. **检查通信**
   - 查看传感器数据是否正常更新
   - 检查DDS通信是否正常

6. **检查初始化**
   - 查看 `ref_joint_act` 是否正确
   - 检查初始化时关节位置是否正确读取

## 六、总结

**高风险区域**：

1. ⚠️ **RL模式缺少速度限制**（最危险）
2. ⚠️ **没有加速度限制**
3. ⚠️ **缺少电机状态监控**（merror）
4. ⚠️ **没有数值异常检查**（NaN/Inf）
5. ⚠️ **位置误差监控不足**（仅在stand模式有）

**建议优先级**：

1. **高优先级**：添加RL模式速度限制
2. **高优先级**：添加数值异常检查
3. **中优先级**：添加位置误差持续监控
4. **中优先级**：添加电机状态检查
5. **低优先级**：添加加速度限制
