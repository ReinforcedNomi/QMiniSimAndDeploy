### 系统架构图

```
┌─────────────────────────────────────────────────────────────┐
│                     主程序入口                                │
│                  run_interface.cpp                           │
│                      ↓                                        │

                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
        ▼                   ▼                   ▼
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ 控制线程     │   │ 命令写入线程 │   │ IMU读取线程  │
│ Control()    │   │JointState...│   │IMUState...   │
│ 15ms周期     │   │ 2ms周期     │   │ 3ms周期      │
└──────────────┘   └──────────────┘   └──────────────┘

┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ RLController │   │MotorController│  │  DataBuffer │

└──────────────┘   └──────────────┘   └──────────────┘
```

### 核心组件

1. **G1类**：主控制器，协调所有子系统
2. **RLController类**：强化学习控制器，执行ONNX推理
3. **MotorController类**：电机通信控制器，通过串口与电机通信
4. **DataBuffer**：线程安全的数据缓冲区，用于线程间数据交换
5. **ModeSwitcher类**：模式切换管理器，处理手柄/键盘输入

## 核心类与函数详解

### 1. run_interface.cpp（主程序入口）

**文件作用**：程序入口点，创建G1对象并保持程序运行。

**函数说明**：

```cpp
int main(int argc, char const *argv[])
```
- **功能**：程序主入口
- **参数**：
  - `argc`：命令行参数数量
  - `argv`：命令行参数数组
- **执行流程**：
  1. 创建G1对象，传入网络接口名称（"lo"）和测试模式标志
  2. 进入无限循环，保持程序运行
- **调用关系**：
  - 创建 `G1` 对象 → 触发G1构造函数

### 2. G1类（主控制器）

**文件**：`include/user/custom.hpp`, `src/user/custom.cpp`

**类作用**：系统主控制器，负责：
- 初始化所有子系统
- 创建和管理所有线程
- 协调各模块之间的数据交换
- 实现控制循环和模式切换

#### 2.1 构造函数 `G1::G1()`

**功能**：初始化整个系统

**执行流程**：
1. 初始化DDS通道工厂
2. 初始化手柄/游戏手柄
3. 创建RLController对象并初始化
4. 连接数据缓冲区：
   ```cpp
   rlController->dds_motor_command = &motor_command_buffer_;
   rlController->dds_motor_state = &motor_state_buffer_;
   rlController->dds_base_state = &base_state_buffer_;
   ```
5. 创建所有线程：
   - `control_thread_ptr_`：控制线程（15ms周期）
   - `command_writer_ptr_`：命令写入线程（2ms周期）
   - `imu_thread_ptr_`：IMU读取线程（3ms周期）
   - `report_rpy_ptr_`：数据报告线程（15ms周期）
   - `mode_process_ptr_`：模式处理线程（20ms周期）

**调用关系**：
- 调用 `RLController::init()` → 初始化RL控制器
- 调用 `RLController::reset()` → 重置RL控制器状态

#### 2.2 `G1::Control()` - 控制循环核心函数

**功能**：主控制循环，每个控制周期（15ms）执行一次

**执行流程**：
1. 更新相对时间：`relative_time += control_dt_`
2. 转换DDS状态到RL状态：`rlController->convert_dds_state2rl_state()`
3. 根据当前模式执行相应控制：
   - `'1'`：关节浮空模式（默认）
   - `'2'`：站立模式 → 调用 `stand_control()`
   - `'3'`：RL行走模式 → 调用 `rl_control()`，前2帧执行 `stand_control()`
   - `'5'`：正弦测试模式
   - `'q'`：退出程序
4. 将控制指令写入缓冲区：`set_rl_joint_act2dds_motor_command()`
5. 打印日志（按配置频率）

**调用关系**：
- 调用 `RLController::convert_dds_state2rl_state()` → 读取传感器数据
- 调用 `RLController::stand_control()` → 站立控制
- 调用 `RLController::rl_control()` → RL控制
- 调用 `RLController::set_rl_joint_act2dds_motor_command()` → 写入命令缓冲区

**关键代码**：
```cpp
void G1::Control() {
    relative_time += control_dt_;
    float ratio = fmin(relative_time / MOVE_DURATION, 1.f);
    rlController->convert_dds_state2rl_state();
    switch (current_mode) {
        case '2':
            rlController->stand_control(ratio);
            break;
        case '3':
            rlController->rl_control();
            if (rlController->counter_rl < 2)
                rlController->stand_control(ratio);
            break;
        // ...
    }
    rlController->set_rl_joint_act2dds_motor_command(current_mode);
}
```

#### 2.3 `G1::ModeProcess()` - 模式切换处理

**功能**：处理模式切换逻辑，每20ms执行一次

**执行流程**：
1. 根据测试模式或正常模式获取选中的模式
2. 检测模式是否变化
3. 如果模式变化：
   - 重置相对时间：`relative_time = 0.`
   - 更新当前模式：`current_mode = selected_mode`
   - 调用 `rlController->reset()` 重置RL控制器
   - **如果切换到站立模式（'2'）**：清空电机命令缓冲区
4. 更新RL任务模式

**调用关系**：
- 调用 `ModeSwitcher::get_selected_key()` / `get_selected_jskey()` → 获取模式
- 调用 `RLController::reset()` → 重置RL控制器

**关键代码**：
```cpp
void G1::ModeProcess() {
    if (_is_test_local) {
        selected_mode = modeSwitcher.get_selected_key(current_mode);
    } else {
        selected_mode = modeSwitcher.get_selected_jskey(current_mode);
    }
    if (selected_mode != current_mode) {
        relative_time = 0.;
        current_mode = selected_mode;
        rlController->reset(_is_test_local);
        
        // 切换到站立模式时，清空电机位置控制的数据
        if (selected_mode == '2') {
            MotorCommand empty_command;
            // ... 设置为0 ...
            motor_command_buffer_.SetData(empty_command);
        }
    }
}
```

#### 2.4 `G1::JointStateReadWriter()` - 命令写入线程

**功能**：将控制命令发送给电机，并读取电机反馈，每2ms执行一次

**执行流程**：
1. 调用 `SetMotorCmd()` 获取电机命令
2. 调用 `Motor_control.Run()` 发送命令给电机
3. 调用 `RecordMotorState()` 记录电机反馈状态

**调用关系**：
- 调用 `G1::SetMotorCmd()` → 从缓冲区读取命令
- 调用 `MotorController::Run()` → 发送命令
- 调用 `MotorController::GetData()` → 获取电机反馈
- 调用 `G1::RecordMotorState()` → 写入状态缓冲区

**关键代码**：
```cpp
void G1::JointStateReadWriter() {
    Motor_control.Run(SetMotorCmd());
    RecordMotorState(Motor_control.GetData());
}
```

#### 2.5 `G1::SetMotorCmd()` - 生成电机命令

**功能**：从缓冲区读取MotorCommand，转换为DDS格式的LowCmd

**执行流程**：
1. 从 `motor_command_buffer_` 读取最新的MotorCommand
2. 将MotorCommand转换为DDS格式的LowCmd
3. 返回LowCmd供电机控制器使用

**调用关系**：
- 被 `G1::JointStateReadWriter()` 调用

**关键代码**：
```cpp
unitree_hg::msg::dds_::LowCmd_ G1::SetMotorCmd() {
    const std::shared_ptr<const MotorCommand> mc = motor_command_buffer_.GetData();
    for (size_t i = 0; i < rlController->NUM_JOINTS; i++) {
        dds_low_command.motor_cmd().at(i).q() = mc->q_target[i];
        dds_low_command.motor_cmd().at(i).kp() = mc->kp[i];
        dds_low_command.motor_cmd().at(i).kd() = mc->kd[i];
        // ...
    }
    return dds_low_command;
}
```

#### 2.6 `G1::RecordMotorState()` - 记录电机状态

**功能**：将电机反馈数据写入状态缓冲区

**执行流程**：
1. 从MotorData数组提取数据
2. 填充MotorState结构
3. 写入 `motor_state_buffer_`

**调用关系**：
- 被 `G1::JointStateReadWriter()` 调用

#### 2.7 `G1::IMUStateReader()` - IMU读取线程

**功能**：读取IMU数据并写入缓冲区，每3ms执行一次

**执行流程**：
1. 调用 `imuReader.fetchIMUData()` 读取IMU数据
2. 调用 `RecordBaseState()` 写入BaseState缓冲区

**调用关系**：
- 调用 `IMUReader::fetchIMUData()` → 读取IMU
- 调用 `G1::RecordBaseState()` → 写入缓冲区

#### 2.8 `G1::ReportData()` - 数据报告线程

**功能**：记录RL控制数据到文件，每15ms执行一次

**执行流程**：
1. 检查当前模式和counter_rl计数
2. 如果满足条件，调用 `dataReporter.report_data()` 记录数据

**调用关系**：
- 调用 `DataReporter::report_data()` → 记录数据

### 3. RLController类（RL控制器）

**文件**：`include/user/rl_controller.h`, `src/user/rl_controller.cpp`

**类作用**：强化学习控制器，负责：
- ONNX模型推理
- 关节目标位置计算
- 观测数据构建
- 控制指令生成

#### 3.1 `RLController::init()` - 初始化

**功能**：初始化RL控制器

**执行流程**：
1. 加载ONNX模型：`motion_session = new Ort::Session(...)`
2. 初始化ONNX推理器：`onnxInference.init(...)`
3. 初始化所有状态变量为0
4. 从配置文件加载参数（关节限位、刚度、阻尼等）
5. 初始化观测堆叠缓冲区

**调用关系**：
- 被 `G1::G1()` 构造函数调用

#### 3.2 `RLController::reset()` - 重置状态

**功能**：重置RL控制器状态，在模式切换时调用

**执行流程**：
1. 重置相位频率：`pm_f.setConstant(0.5f)`
2. 重置相位：`_pm_phase << 0, 0`
3. 重置目标命令：`target_command.setZero()`
4. 重置计数器：`counter_rl = 0`, `_is_first_run = true`
5. **关键**：根据模式设置 `joint_act`：
   - 测试模式：`joint_act = joint_act`（保持）
   - 正常模式：`joint_act = joint_pos`（设置为当前实际位置）

**调用关系**：
- 被 `G1::ModeProcess()` 调用

**关键代码**：
```cpp
void RLController::reset(bool is_test_local) {
    pm_f.setConstant(0.5f);
    _pm_phase << 0, 0;
    target_command.setZero();
    _is_first_run = true;
    counter_rl = 0;
    if (is_test_local) {
        init_joint_act = joint_act;
        joint_pos = joint_act;
    } else {
        convert_dds_state2rl_state();  // 读取当前实际位置
        joint_act = joint_pos;          // ⭐ 重置为当前实际位置
        init_joint_act = joint_pos;
        _record_yaw = base_rpy[2];
    }
    auto o = get_observation();
}
```

#### 3.3 `RLController::rl_control()` - RL控制主函数

**功能**：执行RL控制，包括ONNX推理和关节位置更新

**执行流程**：
1. 增加RL计数器：`counter_rl++`
2. 获取观测：`get_observation()` → 构建43维观测向量
3. ONNX推理：`onnxInference.inference()` → 输出12维动作增量
4. 转换动作：`transform()` → 将归一化输出转换为实际增量
5. 更新关节位置：`joint_increment_control()` → 增量更新 `joint_act`
6. 更新时间步长：`get_true_loop_period()`

**调用关系**：
- 调用 `RLController::get_observation()` → 构建观测
- 调用 `OnnxInference::inference()` → ONNX推理
- 调用 `RLController::transform()` → 动作转换
- 调用 `RLController::joint_increment_control()` → 更新关节位置

**关键代码**：
```cpp
void RLController::rl_control() {
    counter_rl++;
    Matrix<float, Dynamic, 1> net_out;
    net_out = onnxInference.inference(motion_session, get_observation());
    action_increment = transform(net_out);
    joint_increment_control(action_increment);
    _rl_time_step = get_true_loop_period();
}
```

#### 3.4 `RLController::joint_increment_control()` - 关节增量控制

**功能**：根据动作增量更新关节目标位置

**执行流程**：
1. 提取相位频率：`pm_f = increment.segment(0, NUM_LEGS)`
2. 计算相位：`compute_pm_phase(pm_f)`
3. **关键**：增量更新关节位置：
   ```cpp
   joint_act.segment(0, NUM_ACTUAT_JOINTS) += 
       increment.segment(NUM_LEGS, NUM_ACTUAT_JOINTS) * _rl_time_step;
   ```
4. 限位保护：`joint_act = joint_act.cwiseMax(act_pos_low).cwiseMin(act_pos_high)`

**调用关系**：
- 被 `RLController::rl_control()` 调用
- 调用 `RLController::compute_pm_phase()` → 更新相位

**关键代码**：
```cpp
void RLController::joint_increment_control(Matrix<float, Dynamic, 1> increment) {
    pm_f = increment.segment(0, NUM_LEGS);
    compute_pm_phase(pm_f);
    joint_act.segment(0, NUM_ACTUAT_JOINTS) += 
        increment.segment(NUM_LEGS, NUM_ACTUAT_JOINTS) * _rl_time_step;
    joint_act = joint_act.cwiseMax(act_pos_low).cwiseMin(act_pos_high);
}
```

#### 3.5 `RLController::set_rl_joint_act2dds_motor_command()` - 写入命令缓冲区

**功能**：将 `joint_act` 转换为MotorCommand并写入缓冲区

**执行流程**：
1. 创建MotorCommand对象
2. 将 `joint_act` 复制到 `q_target`（通过jointIndex2Sim映射）
3. 根据模式设置kp/kd：
   - `'q'` 或 `'x'`：kp=0, kd=0（泄力）
   - `'1'`：使用软刚度/阻尼
   - 其他：使用正常刚度/阻尼
4. 设置其他参数：`dq_target=0`, `tau_ff=0`
5. 写入缓冲区：`dds_motor_command->SetData(motor_command_tmp)`

**调用关系**：
- 被 `G1::Control()` 调用

**关键代码**：
```cpp
void RLController::set_rl_joint_act2dds_motor_command(char mode) {
    MotorCommand motor_command_tmp;
    for (int i = 0; i < NUM_JOINTS; ++i) {
        motor_command_tmp.q_target[i] = joint_act[jointIndex2Sim[i]];
        // ... 设置kp, kd等 ...
    }
    dds_motor_command->SetData(motor_command_tmp);
}
```

#### 3.6 `RLController::convert_dds_state2rl_state()` - 状态转换

**功能**：从DataBuffer读取传感器数据，转换为RL控制器内部状态

**执行流程**：
1. 读取电机状态：从 `dds_motor_state` 读取关节位置、速度、扭矩
2. 指数滤波：对位置和速度进行滤波平滑
3. 读取基座状态：从 `dds_base_state` 读取IMU数据（rpy、角速度、加速度）
4. 坐标转换：应用转换轴 `trans_axis(-1., 1, -1)`

**调用关系**：
- 被 `G1::Control()` 调用
- 被 `RLController::reset()` 调用

**关键代码**：
```cpp
void RLController::convert_dds_state2rl_state() {
    Vec3<float> trans_axis(-1., 1, -1);
    if (dds_motor_state->GetData()) {
        for (int i = 0; i < NUM_JOINTS; ++i) {
            joint_pos[jointIndex2Sim[i]] = 
                exp_filter(joint_pos[jointIndex2Sim[i]], 
                          dds_motor_state->GetData()->q[i], 0.2);
            joint_vel[jointIndex2Sim[i]] = 
                exp_filter(joint_vel[jointIndex2Sim[i]], 
                          dds_motor_state->GetData()->dq[i], 0.1);
            // ...
        }
    }
    // ... 读取IMU数据 ...
}
```

#### 3.7 `RLController::stand_control()` - 站立控制

**功能**：平滑过渡到参考站立姿态

**执行流程**：
1. 调用 `smooth_joint_action()` 进行平滑插值
2. 从 `init_joint_act` 平滑过渡到 `_ref_joint_act`

**调用关系**：
- 被 `G1::Control()` 调用
- 调用 `RLController::smooth_joint_action()` → 平滑插值

#### 3.8 `RLController::get_observation()` - 构建观测向量

**功能**：构建43维观测向量，用于ONNX模型输入

**执行流程**：
1. 计算关节位置误差：`joint_pos_error = joint_act - joint_pos`
2. 计算相位正弦余弦：`sin(_pm_phase)`, `cos(_pm_phase)`
3. 处理手柄命令：`joystick_command_process()`
4. 构建观测向量（43维）：
   - 基座姿态（rpy）
   - 基座角速度
   - 关节位置误差
   - 关节速度
   - 相位信息
   - 目标命令
   - 等等
5. 观测堆叠：将3帧观测堆叠成129维向量

**调用关系**：
- 被 `RLController::rl_control()` 调用
- 调用 `RLController::joystick_command_process()` → 处理手柄命令

## 线程架构

### 线程列表

| 线程名称 | 周期 | 函数 | 功能 |
|---------|------|------|------|
| control_thread | 15ms | `G1::Control()` | 主控制循环，计算控制指令 |
| command_writer | 2ms | `G1::JointStateReadWriter()` | 发送命令给电机，读取反馈 |
| imu_thread | 3ms | `G1::IMUStateReader()` | 读取IMU数据 |
| report_rpy | 15ms | `G1::ReportData()` | 记录数据到文件 |
| mode_process | 20ms | `G1::ModeProcess()` | 处理模式切换 |

### 线程间通信

使用 `DataBuffer` 进行线程安全的数据交换：

```

    ↑ GetData()

电机反馈
    ↓ SetData()
motor_state_buffer_ (DataBuffer<MotorState>)
    ↑ GetData()
控制线程 (Control)

IMU数据
    ↓ SetData()
base_state_buffer_ (DataBuffer<BaseState>)
    ↑ GetData()
控制线程 (Control)
```

### 关键数据结构

**joint_act（目标位置）**：
- 类型：`Vec10<float>`
- 作用：存储10个关节的目标位置（rad）
- 更新方式：
  - RL模式：`joint_act += action_increment * dt`（增量更新）
  - 站立模式：`joint_act = smooth_interpolation()`（平滑插值）
  - 模式切换：`joint_act = joint_pos`（重置为当前位置）

**joint_pos（当前位置）**：
- 类型：`Vec10<float>`
- 作用：存储10个关节的实际位置（rad）
- 更新方式：从电机反馈读取，指数滤波

**motor_command_buffer_（命令缓冲区）**：
- 类型：`DataBuffer<MotorCommand>`
- 作用：线程安全的单帧缓冲区，存储最新的电机命令
- 更新频率：每个控制周期（15ms）更新一次

## 第二次进入RL模式角度插针问题分析

### 问题现象

**问题描述**：第二次从站立模式切换到RL模式时，目标角度（joint_act）会突然跳到限位位置。

### 问题原因分析

#### 1. 数据流转时序问题

**第一次进入RL模式**：
```
时刻 T0: 站立模式运行中
  - joint_pos = [0.5, 0.2, -1.5, ...] (实际位置)
  - joint_act = [0.55, 0.25, -1.35, ...] (站立目标位置)

时刻 T1: 切换到RL模式
  - reset() 执行
  - convert_dds_state2rl_state() 读取当前实际位置
  - joint_pos = [0.5, 0.2, -1.5, ...] (更新)
  - joint_act = joint_pos = [0.5, 0.2, -1.5, ...] (重置为当前位置)

时刻 T2: RL模式第一帧
  - rl_control() 执行
  - get_observation() 构建观测（基于 joint_pos）
  - ONNX推理 → action_increment
  - joint_act += action_increment * dt
  - joint_act = [0.5, 0.2, -1.5, ...] + [0.05, 0.05, 0.15, ...] * 0.015
  - joint_act = [0.50075, 0.20075, -1.49775, ...] (正常)
```

**第二次进入RL模式**：
```
时刻 T0: 站立模式运行中
  - joint_pos = [0.5, 0.2, -1.5, ...] (实际位置)
  - joint_act = [0.55, 0.25, -1.35, ...] (站立目标位置)

时刻 T1: 切换到RL模式
  - reset() 执行
  - convert_dds_state2rl_state() 读取当前实际位置
  - ⚠️ 问题：如果此时 motor_state_buffer_ 中还是旧数据
  - joint_pos 可能读取到错误的值
  - joint_act = joint_pos (可能已经是错误的值)

时刻 T2: RL模式第一帧
  - rl_control() 执行
  - get_observation() 构建观测（基于错误的 joint_pos）
  - ONNX推理 → action_increment
  - joint_act += action_increment * dt
  - ⚠️ 如果 joint_pos 已经是限位值，joint_act 也会跳到限位
```

#### 2. 缓冲区清空时机问题

**当前实现**：
```cpp
// 切换到站立模式时清空缓冲区
if (selected_mode == '2') {
    MotorCommand empty_command;
    // ... 设置为0 ...
    motor_command_buffer_.SetData(empty_command);
}
```

**问题**：
- 清空的是 `motor_command_buffer_`（命令缓冲区）
- 但 `motor_state_buffer_`（状态缓冲区）没有被清空
- 如果状态缓冲区中有旧数据，`convert_dds_state2rl_state()` 会读取到错误的值

#### 3. joint_act 累积问题

**RL控制使用增量更新**：
```cpp
joint_act.segment(0, NUM_ACTUAT_JOINTS) += 
    increment.segment(NUM_LEGS, NUM_ACTUAT_JOINTS) * _rl_time_step;
```

**问题场景**：
1. 第一次RL模式结束时，`joint_act` 可能已经累积到接近限位
2. 切换到站立模式时，`reset()` 将 `joint_act = joint_pos`
3. 但如果 `joint_pos` 读取错误（例如读取到限位值）
4. 第二次进入RL模式时，`joint_act` 从错误的初始值开始
5. 加上RL增量，很容易超过限位

#### 4. 观测堆叠问题

**观测堆叠机制**：
```cpp
// obs_stack 存储3帧历史观测
for (int i(0); i < onnxInference.stack_dim; i++) {
    // 滑动窗口更新
}
```

**问题**：
- 如果 `obs_stack` 中还有上一次RL模式的历史观测
- 第二次进入RL模式时，这些旧观测会影响推理结果
- 可能导致输出异常的动作增量

### 解决方案

#### 方案1：在reset()中清空观测堆叠

```cpp
void RLController::reset(bool is_test_local) {
    // ... 现有代码 ...
    
    // 清空观测堆叠
    for (int i(0); i < onnxInference.stack_dim; i++) {
        obs_stack.at(i).setZero(onnxInference.input_dim);
    }
    _is_first_run = true;  // 标记为首次运行，重新填充观测堆叠
}
```

#### 方案2：确保读取最新状态

```cpp
void RLController::reset(bool is_test_local) {
    // ... 现有代码 ...
    
    if (!is_test_local) {
        // 多次读取，确保获取最新状态
        for (int i = 0; i < 3; ++i) {
            convert_dds_state2rl_state();
            usleep(1000);  // 等待1ms
        }
        joint_act = joint_pos;
        init_joint_act = joint_pos;
    }
}
```

#### 方案3：在切换到RL模式时也清空缓冲区

```cpp
// 在 ModeProcess() 中
if (selected_mode == '3') {
    // 切换到RL模式时，确保状态缓冲区是最新的
    rlController->convert_dds_state2rl_state();
    // 清空观测堆叠
    // ...
}
```

### 根本原因总结

**核心问题**：
1. **状态缓冲区数据不同步**：`motor_state_buffer_` 中可能还有旧数据
2. **观测堆叠未清空**：`obs_stack` 中保留了上一次RL模式的观测
3. **joint_act 初始值错误**：如果 `joint_pos` 读取错误，`joint_act` 也会错误

**最可能的原因**：
- `convert_dds_state2rl_state()` 在 `reset()` 中读取状态时，`motor_state_buffer_` 中可能还是上一次RL模式结束时的数据
- 如果上一次RL模式结束时，电机位置已经接近限位，读取到的 `joint_pos` 就是限位值
- 第二次进入RL模式时，`joint_act` 从限位值开始，加上RL增量，很容易超过限位

## 总结

### 关键要点

1. **DataBuffer是单帧缓冲区**：只存储最新的一帧数据，每次 `SetData()` 都会覆盖
2. **模式切换会重置状态**：`reset()` 会将 `joint_act` 重置为当前实际位置
3. **RL控制使用增量更新**：`joint_act += increment * dt`，需要正确的初始值
4. **观测堆叠需要清空**：模式切换时应该清空 `obs_stack`，避免旧观测影响推理
5. **状态读取需要同步**：确保 `convert_dds_state2rl_state()` 读取的是最新状态

### 数据流转关键路径

```
传感器 → DataBuffer → Control() → RLController → joint_act → 
DataBuffer → JointStateReadWriter() → MotorController → 电机
```

### 模式切换关键步骤

1. 检测模式变化
2. 调用 `reset()` 重置状态
3. 清空相关缓冲区（站立模式）
4. 更新当前模式
5. 下一个控制周期开始新模式的控制
